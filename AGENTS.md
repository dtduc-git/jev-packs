# jev-packs — agent notes

## What this is

Golden-set benchmark and evidence-gated registry of Jev question packs:
canonical pack format spec v0, curated question sets with golden cases,
`index.json`, and `results/` — independent benchmark columns for Jev and
alternative backends, published as `docs/index.html` (Jev Bench).

- GitHub: https://github.com/dtduc-git/jev-packs
- Suite: `jevassert` (runner, owns loader + gates) → **jev-packs** (data +
  spec + benchmark) → `jev-table` (app).
- The canonical spec is [SPEC.md](SPEC.md); `ideas/jev-packs.md` in the private
  brainstorm repo is the strategy doc and must stay in sync with SPEC.md.

## Current state (2026-09-19)

- Spec v0 + validator + CI + **9 packs · 2,990 cases / 6,430 items, all
  `verified` against `jev-1.13.0`** (accuracy 0.840–0.967, ECE 0.017–0.090).
  Six hand-written packs plus three dataset-derived packs (sms-spam,
  banking-intent, boolq-yes-no). Each pack has `tested`, `evidence.md` and
  `predictions.jsonl`.
- **Benchmark layer added**: `results/<backend>/` (backend.json + per-pack
  json/md/predictions), `docs/index.html` generated by
  `scripts/build_scoreboard.py`, `scripts/record-backend.py` (TypeSafe or any
  LLM via the official `system-one-adapter`), `scripts/verify_results.py`
  (offline replay of committed results), METHODOLOGY.md.
- jevassert 0.2.0 required for recording/verifying results (adapter backends +
  `--input-price/--output-price`); release it before merging result PRs.
- No gates.yaml yet — packs pass no declared minimum. Add gates from measured
  baselines when the numbers are stable enough to gate (see Next steps).

## Layout

- `packs/<id>/pack.yaml` — questions (noul | choice | score) + thresholds.
- `packs/<id>/cases.jsonl` — golden cases; `expect` covers every question.
- `packs/<id>/README.md` — purpose, provenance, rationale.
- `results/<backend>/backend.json` — how to reproduce the column (model,
  endpoint, license, pricing, settings).
- `results/<backend>/<pack>.{json,md,predictions.jsonl}` — metrics, report,
  raw recording (predictions are the source of truth; hash-checked).
- `scripts/validate.py` — CI entry point; stdlib + PyYAML; validates packs,
  index.json and results/.
- `scripts/refresh.py` — re-records Jev packs, regenerates `evidence.md`,
  writes `results/<jev-version>/`, updates `index.json`, validates + rebuilds
  the scoreboard. Called by the Refresh evidence workflow.
- `scripts/record-backend.py` — records a benchmark backend (see
  METHODOLOGY.md); `scripts/build_scoreboard.py` — generates `docs/index.html`.
- `index.json` — registry listing; must exactly match `packs/`.

## Conventions

- Verify before claiming done:
  `uv run --no-project --with pyyaml python scripts/validate.py`
  and `python3 scripts/build_scoreboard.py --check`.
- Every Choice/Score closed set must include `unknown` (Jev cannot abstain).
- Gold labels come from the state alone; no outside context.
- Never hand-edit `evidence.md`, `results/`, or set `tested` without a real
  jevassert run; recordings are the source of truth and are hash-checked.
- Cases stay CC0; dataset-derived packs keep upstream license + attribution.
- Keep pack ids stable once listed; breaking question changes bump the pack
  minor version and are noted in its CHANGELOG.
